# retrieval-sweep

Deterministic, LLM-free, label-free code-retrieval evaluation across
four corpora and four design axes. Self-contained under this directory.

```
.
├── DESIGN.md                  pre-registered hypotheses + method
├── REPORT.md                  results, regenerated by F_analyze.py
├── paper/PAPER.md             paper draft (same data, different audience)
├── scripts/                   all the Python (no third-party deps for the CPU sweeps)
│   ├── 00_collect_corpus.py   step 1 — clones + subsets + emits corpus.jsonl
│   ├── 01_derive_queries.py   step 2 — auto-derives (query, gold) pairs (zero labels)
│   ├── _common.py, _bm25.py, _dense.py, _hybrid.py, _metrics.py,
│   │   _tokenizers.py, _noise.py, _eval.py, _extractors.py
│   ├── E1_bm25_grid.py        BM25 (k1, b) sweep
│   ├── E2_floor_sweep.py      relative vs absolute floor sweep
│   ├── E3_corpus_size.py      corpus-size scaling sweep
│   ├── E4_dense_models.py     dense encoder sweep (GPU)
│   ├── E5_hybrid_fusion.py    BM25 × dense hybrid sweep (GPU)
│   ├── E6_query_noise.py      query-noise robustness sweep
│   ├── E7_family_ablation.py  per-query-family ablation
│   ├── E8_tokenizer.py        BM25 tokenizer sweep
│   ├── F_analyze.py           aggregate + plots
│   ├── ship_to_gpu.py         pack the sweep into a tarball for the remote
│   ├── test_bm25.py           unit tests for BM25 + tokenizers
│   └── test_hybrid.py         unit tests for fusion + dense mock
├── corpora/                   gitignored — re-clonable from meta.json git_sha
├── queries/                   small per-corpus *.queries.jsonl (cpython ignored — large)
├── results/                   gitignored — per-stage <cfg_id>.{summary.json, rows.jsonl} + INDEX.csv
├── plots/                     gitignored — F_analyze.py output
└── shipment/                  gitignored — ship_to_gpu.py output tarballs
```

## Run

```bash
cd scripts
python 00_collect_corpus.py        # rebuilds corpora/<name>/corpus.jsonl
python 01_derive_queries.py        # rebuilds queries/<name>.queries.jsonl
python -m unittest test_bm25 test_hybrid
python E1_bm25_grid.py
python E2_floor_sweep.py
python E3_corpus_size.py
python E6_query_noise.py
python E7_family_ablation.py
python E8_tokenizer.py
# GPU stages (remote, see scripts/ship_to_gpu.py):
python E4_dense_models.py
python E5_hybrid_fusion.py

python F_analyze.py                # MASTER.csv + plots/
```

## Numbers at a glance

| Quantity | Value |
|---|---:|
| Corpora | 4 (TS×2, Python, Go) |
| Source files | 4,741 |
| Auto-derived (query, gold) pairs | 67,276 |
| Query families | 7 |
| BM25 (k1, b) grid cells | 35 per corpus |
| Floor strategies | 11 per corpus |
| Dense encoders pre-registered | 9 |
| Hybrid fusion configs | 16 per corpus |
| Noise (kind × rate) cells | 26 per corpus |

No LLM calls. No human-labeled data. Reproducible bit-for-bit.

## What this is _not_

- Not an LLM-as-judge eval.
- Not a re-ranker eval.
- Not a fine-tuning study.
- Not a Q&A benchmark.

The sister branch `feat/nightly-verifier-feedback` is where the
stochastic / LLM-judged work happens; this branch was carved out as
its deterministic counterpart.
